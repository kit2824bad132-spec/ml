5. BEST BLOCKING STRATEGY
--------------------------------------------------------------------------------
- Strategy: Selective Multi-Pass Blocking with Bounded Token Co-Occurrence & Deduplication
- Core Blocking Passes (all capped at max 250 candidates per block):
  Pass 1: Exact Normalized Business Name + Country
  Pass 2: Normalized Business Name Prefix (6 chars) + Country
  Pass 3: First Name Token (len >= 5) + Country
  Pass 4: Postal / PIN Code (5-6 digits) + Country
  Pass 5: House Number + Address Token + Country
  Pass 6: Name Token + Address Token + Country
- Deduplication: Strict composite key deduplication across all passes (not simple concatenation).

16. WHICH EXPERIMENTS WERE REJECTED AND WHY
--------------------------------------------------------------------------------
1. Thresholds <= 0.70:
   - Rejected. At threshold 0.70, false positives reached 2,898 on the expanded candidate set, 
     dragging F0.5 down to 0.862923. Threshold 0.975 suppresses false positives to 121.
2. Source-Aware Top-1 / Top-2 Per-Source Truncation:
   - Rejected. 33.7% of Source-1 entities match multiple target entities across S2 and S3.
     Forcing Top-1 dropped recall to 56.24% and F0.5 to 0.8625. Global thresholding preserves multi-matches.
3. Enhanced Strat-4 Blocking (Address-Tail City Union):
   - Rejected. Although it captured 340 more true matches (95.55% candidate recall), it added
     330,000 loose city/address candidates, driving false positives to 567 and lowering F0.5 to 0.936205.
4. Full Cartesian / Unbounded Token Blocking:
   - Rejected. Unbounded single-token blocking created buckets with up to 226,422 candidates,
     exploding candidate volume to over 54M pairs with severe memory/disk degradation.
5. Immediate Full Test Inference:
   - Rejected in accordance with Phase 12 rules, pending user review of final clean-validation
     benchmarks.
